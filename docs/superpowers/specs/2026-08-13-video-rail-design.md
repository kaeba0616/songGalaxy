# 영상 사이드바(우측 레일) — 설계

작성: 2026-08-13
관련 원본: `docs/SSOT.md` (YouTube 무대의 자리, 미리듣기 재생 상태), `docs/superpowers/specs/2026-08-11-playlists-youtube-design.md`

## 무엇을 만드나

목록 전곡 재생 중 뜨는 영상 패널을 **화면 오른쪽 전체 높이 레일**로 바꾸고, 그 안에 지금 재생 목록까지 넣는다. 콘텐츠 페이지의 본문은 레일만큼 자리를 비켜 **더 이상 가려지지 않는다**.

## 왜 지금 하나

2026-08-12에 무대를 알약에서 떼어 레이아웃 최상위(`fixed right-4 top-20`)로 올렸다. 그 덕에 은하는 중앙이 열렸지만, 콘텐츠 페이지는 전부 `mx-auto max-w-3xl`로 가운데 정렬이라 본문 오른쪽 끝과 도크가 겹친다. 실측(1440×900): 본문 우측 끝 1104px, 도크 1004~1424px → `/lists/[id]`의 `✕` 3개 전부, `/songs`의 `+` 버튼이 `elementFromPoint` 기준 IFRAME에 가려 **영상 재생 중에는 곡을 뺄 수도 담을 수도 없다**.

## 제약

- **iframe은 DOM에서 부모가 바뀌면 문서를 새로 로드한다** — 재생이 처음부터 다시 시작된다. 그래서 무대는 지금처럼 레이아웃 최상위에 딱 한 번 마운트된 채로 두고, 모양 전환은 **CSS만으로** 한다(반응형 클래스, `hidden`).
- **접기 = 일시정지**는 약관이며 `PlayerProvider.setVideoExpanded`에 있다. 레일이 되어도 그대로다.
- 영상 세로는 `VIDEO_MIN_PX`(200) 밑으로 내려갈 수 없다(YouTube 개발자 정책). 레일 폭 360px → 16:9 세로 202px로 통과한다.
- **새 npm 패키지를 설치할 수 없다** (`npm install`이 멈춘다).

## 결정 사항

| 질문 | 결정 | 이유 |
| --- | --- | --- |
| 레일 모양 | 넓은 화면(`sm` 이상)은 우측 전체 높이 레일, 좁은 화면은 지금의 떠 있는 카드 | 폰에는 세로 레일을 둘 폭이 없다 |
| 은하 | 레일이 **겹친다**(자리를 비우지 않는다) | 은하 캔버스는 `window.resize`만 듣는다. 폭을 밀면 다음 창 크기 변경 전까지 화면이 늘어난 채 남는다. 전체 화면 캔버스는 겹쳐도 무방하고, 레일이 우측 끝에 붙으면 지금(우측 상단 카드)보다 성단을 덜 가린다 |
| 콘텐츠 페이지 | 레일/카드만큼 **자리를 비운다** | 가려지는 문제의 본체다 |
| 레일에 무엇을 넣나 | 영상 + 지금 재생 목록 | 알약을 열지 않아도 다음 곡을 보고 고를 수 있다 |

## 콘텐츠와 은하를 가르는 방법

`<main>`을 쓰는 곳은 콘텐츠 페이지 7곳뿐이고(`credits`, `list/[slug]`, `lists`, `lists/[id]`, `me`, `songs`, `songs/[id]`), 은하(`/`, `/planet/[id]`)는 `GalaxyCanvas`를 `<main>` 없이 그대로 렌더한다. 그래서 `globals.css`의 규칙 하나가 정확히 갈라준다 — **페이지는 한 줄도 고치지 않는다.**

```css
/* 영상이 떠 있는 동안 본문이 그 아래로 깔리지 않게 자리를 비운다.
   은하는 <main>을 쓰지 않으므로 이 규칙에 걸리지 않는다 — 전체 화면 캔버스 위에는 겹치는 게 맞다 */
main {
  padding-right: var(--video-rail-w, 0px);
  padding-top: var(--video-rail-h, 0px);
}
```

값은 `VideoStage`가 자기 크기를 `ResizeObserver`로 재서 `document.documentElement.style`에 쓴다. 픽셀을 하드코딩하지 않으므로 영상 크기·접기 버튼·글꼴이 바뀌어도 따라온다. 넓은 화면에서는 `--video-rail-w`만, 좁은 화면에서는 `--video-rail-h`만 채우고 나머지는 `0px`로 둔다. 무대가 없거나 접히면 둘 다 `0px`이다.

겹쳐 띄운 경로(`@modal`)도 안에 `<main>`이 그대로 있으므로 같은 규칙을 탄다.

## 레일

`src/player/VideoStage.tsx`가 형태만 바뀐다. 마운트 위치·조건(`stageVideoId`)은 그대로다.

- `sm` 이상: `fixed right-0 inset-y-0 w-[360px] border-l flex flex-col` — 위에서부터 영상(16:9, `min-height: VIDEO_MIN_PX`) → 재생 목록(`flex-1 overflow-y-auto`) → 영상 접기 버튼
- `sm` 미만: 지금 그대로 `fixed right-4 top-20 w-[min(92vw,420px)]` 카드. 재생 목록은 넣지 않는다(알약의 `≡`가 이미 한다)
- 접힘은 지금처럼 `hidden`이며 언마운트하지 않는다 — 내리면 손잡이가 사라져 이어 들을 수 없다

## 재생 목록은 복사하지 않고 꺼낸다

지금 알약(`MiniPlayer`)의 `≡` 패널 안에 있는 곡 목록을 `src/player/QueueList.tsx`로 빼고, **알약과 레일이 같은 컴포넌트를 쓴다.** 두 벌로 두면 반드시 어긋난다.

`QueueList`는 필요한 것을 `usePlayer()`에서 직접 읽는다(큐·재생 곡·일시정지·미디어·`playInQueue`·`toggle`). 부르는 쪽이 정하는 것은 붙는 자리뿐이다:

```tsx
<QueueList className="..." />   // 알약: 고정 높이 max-h-[45vh]. 레일: flex-1 min-h-0
```

현재 곡으로 스크롤하는 동작과 주변 앨범아트 보강(`fetchMedia`)도 함께 옮긴다 — 목록을 그리는 쪽의 일이다.

## 실패·경계

| 상황 | 처리 |
| --- | --- |
| `ResizeObserver`가 없는 환경 | 변수는 `0px`로 남고 본문은 지금처럼 동작한다(가려질 수 있음). 기능이 죽지는 않는다 |
| 무대 언마운트 | 변수를 `0px`로 되돌린다. 안 하면 영상이 끝난 뒤에도 본문에 빈 여백이 남는다 |
| 레일 폭보다 좁은 데스크톱 창 | `sm`(640px) 미만이면 카드 모양으로 돌아간다 |
| 알약과 레일이 동시에 보이는 경우 | 정상이다. 둘 다 같은 `QueueList`를 그리므로 내용이 어긋나지 않는다 |

## 하지 않는 것

- 레일 접기/펼치기 손잡이 — 접으면 재생이 멈추는 것이 약관이라 기존 "영상 접기" 버튼이 이미 그 역할이다
- 레일 폭 조절 UI
- 폰에서의 세로 레일
- 은하 캔버스를 레일만큼 밀어내기(`ResizeObserver` 도입) — 위 결정대로 겹친다
