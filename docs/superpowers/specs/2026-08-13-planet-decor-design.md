# 행성 꾸미기 — 설계

작성: 2026-08-13
관련 원본: `docs/SSOT.md` (행성 테마 팔레트, 곡 좌표 수학), 이슈 #10 (꾸미기)

## 무엇을 만드나

개인 행성(밤하늘)에 **오브젝트를 놓을 수 있게** 한다. 카탈로그에서 켜고 끄면 되고, 놓이는 자리는 앱이 정한다. 방문자에게도 주인이 꾸민 대로 보인다.

## 지금 행성에 있는 것

`GalaxyCanvas`의 `enterSky`가 착륙할 때 만든다. 서 있는 지점을 `C`, 위쪽을 `up = (0,1,0)`이라 하면:

| | 내용 |
| --- | --- |
| 하늘 돔 | 반경 750 구, `C` 중심. 테마의 `zenith`/`horizon`/`glow` 색 |
| 지면 | 반경 300 구, 중심 `C - up*298.5` → **꼭대기가 `C + up*1.5`**. 테마의 `ground` 색 + 발밑 별빛 글로우 |
| 언덕 실루엣 | 반경 620의 원형 능선, 밑동 `C.y - 40`, 높이 `C.y + 10~40`. `hashString("hill:" + userId)` 시드로 굴곡이 사람마다 다르다 |
| 좋아요 곡 별 | 반경 430 돔 위 골든앵글 나선. 최근 곡일수록 눈높이, 오래될수록 천정 |
| 잔별 900개 / 유성 | 장식 |

즉 **"꾸미기"는 색 조합 4개 중 고르기가 전부**이고 나머지는 전부 자동 생성이다. 자유 배치 UI가 없어도 어색하지 않은 이유이기도 하다 — 이 행성은 원래 "알아서 만들어진 내 자리"다.

## 결정 사항

| 질문 | 결정 | 이유 |
| --- | --- | --- |
| 꾸미기의 범위 | 행성에 오브젝트 놓기 | ⑤ 이미지→3D 캐릭터가 "카탈로그에 내 것이 하나 느는" 형태로 그대로 얹힌다 |
| 오브젝트의 자리 | **앱이 정한다** (userId+slug 해시) | 3D 배치 UI 없이 바로 쓸 수 있고, 나중에 자유 배치로 넓힐 때 이 값이 기본값이 된다 |
| 오브젝트의 형태 | 코드로 만드는 절차적 도형 | 모델 파일도 로더도 저장소도 필요 없다. 지금 행성이 전부 이 방식이라 톤이 맞는다 |
| 해금·재화 | **없다. 전부 열려 있다** | 사용자 결정 |
| 방문자에게 보이나 | 보인다 | 테마와 같은 방침 |

## 카탈로그

`src/config/planet-decor.ts`가 원본이다. 항목마다 `slug` · `label` · `place`(`"ground" | "sky"`)를 둔다.

| slug | label | place | 생김새 |
| --- | --- | --- | --- |
| `moon` | 달 | sky | 은은하게 빛나는 구, 지평선 위 |
| `trees` | 나무 | ground | 원뿔 + 기둥, 서너 그루 무리 |
| `rocks` | 바위 | ground | 저폴리 다면체 두어 개 |
| `obelisk` | 오벨리스크 | ground | 위로 좁아지는 기둥, 테마 글로우 색 발광 |
| `lighthouse` | 등대 | ground | 기둥 + 천천히 도는 빛줄기 |
| `lake` | 호수 | ground | 반투명 원반, 글로우 색 반사 |

**기하 생성은 카탈로그 파일에 넣지 않는다.** 카탈로그는 "무엇이 있는가"(서버·UI도 읽는다), 생성은 `src/galaxy/planet-decor-objects.ts`가 맡는다(three.js를 import하므로 서버 코드가 끌어오면 안 된다). 둘을 잇는 것은 `slug`다.

색은 테마에서 받는다 — 오브젝트별 색 지정은 하지 않는다.

## 자리 계산

언덕이 `hashString("hill:" + userId)`를 쓰듯, 오브젝트는 `hashString(userId + ":" + slug)` → `mulberry32`로 각도·거리·크기를 흔든다(둘 다 `src/lib/layout-math.ts`에 이미 있다). 같은 사람의 같은 오브젝트는 늘 같은 자리에 있고, 사람마다 다르다.

**지면 오브젝트**는 수평 거리 `d ∈ [60, 240]`에 놓는다. 지면이 반경 300 구라서 `d`가 300에 가까우면 표면이 급히 꺼지고 300을 넘으면 지면이 아예 없다. 그 거리에서의 지면 높이는

```
y = (C.y - 298.5) + sqrt(300² - d²)
```

(`d=60`이면 `C.y - 4.56`, `d=240`이면 `C.y - 118.5`.) 오브젝트는 이 지점에 놓고 **위쪽이 `up`을 향하게** 세운다 — 구면이라 멀수록 기울어 보이는 것이 자연스럽지만, 그 정도 거리에서는 세워두는 편이 낫다.

크기는 언덕(높이 10~40)과 견줘 정한다: 나무 8~14, 바위 3~6, 오벨리스크 20~28, 등대 26~34, 호수 반경 25~40.

**하늘 오브젝트**(달)는 곡 별과 같은 반경 430 돔 위, 고도 25~40°에 둔다. 곡 별(고도 14~84°)과 라벨을 가리지 않도록 방위는 해시로 흩되 고도를 낮게 잡는다.

## 저장

```sql
CREATE TABLE planet_decor (
  user_id  integer NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  slug     text    NOT NULL,
  added_at timestamp NOT NULL DEFAULT now(),
  PRIMARY KEY (user_id, slug)
);
```

`playlist_songs`와 같은 모양이다. 켜고 끄는 것뿐이라 좌표·순서를 저장하지 않는다 — 좌표는 언제나 해시에서 다시 나온다.

**추가 전용 변경이다.** 기존 테이블을 건드리지 않으며, `drizzle-kit push`는 쓰지 않는다(백업 테이블 `songs_backup_dedupe` 등을 지운다). 로컬 Docker와 Neon 양쪽에 같은 SQL을 직접 적용한다.

## 데이터가 흐르는 길

착륙할 때 이미 부르는 `GET /api/users/[id]/likes`가 주인 정보(소개·성단 분포·대표곡)를 함께 내려준다. 여기에 `decor: string[]`을 얹는다 — 새 엔드포인트도, `/api/stars` 변경도 없다.

`GalaxyCanvas`는 그 응답을 `pendingSky`에 담아 두었다가 `enterSky`에서 쓴다. 지금 `songIds`만 넘기는 자리에 `decor`도 함께 넘긴다.

## UI

`/me`의 "내 행성 테마" 섹션 바로 아래에 "행성 꾸미기"를 둔다. 카탈로그를 칩으로 늘어놓고 눌러 켜고 끈다. 테마 고르기가 쓰는 서버 액션(`setPlanetThemeAction`) 패턴을 그대로 따라 `togglePlanetDecorAction`을 만든다.

별이 없으면(좋아요 `MIN_LIKES_FOR_STAR`곡 미만) 행성 자체가 없으므로 테마 섹션과 같이 숨긴다.

## 실패·경계

| 상황 | 처리 |
| --- | --- |
| 저장된 slug가 카탈로그에 없다(항목을 뺀 뒤) | 조용히 건너뛴다. 지우지 않는다 — 항목이 돌아오면 다시 보이는 편이 낫다 |
| 로그인 안 한 채 토글 요청 | 서버 액션이 아무 일도 하지 않는다 |
| 남의 `user_id`로 토글 | 세션의 id만 쓴다. 요청 본문에서 user id를 받지 않는다 |
| 행성→행성 이동 | `exitSky`가 `skyGroup`을 통째로 dispose하므로 앞 사람 오브젝트가 남지 않는다. 새 오브젝트도 반드시 `skyGroup`에 넣는다 |

## 테스트

`node:test`로 검증할 수 있는 것은 순수 함수뿐이다(이 저장소에는 DOM 하네스가 없고 `npm install`이 멈춰 추가할 수도 없다). 그래서 자리 계산을 순수 함수로 떼어 `src/config/planet-decor.ts` 옆에 두고 테스트한다:

- `decorPlacement(userId, slug)` → `{ angle, distance, scale }` — 같은 입력이면 늘 같은 값, 사람·항목마다 다른 값, 거리는 `[60, 240]` 안
- `groundHeight(distance)` → 위 공식, `d=0`에서 `+1.5`, `d≥300`이면 지면 밖이므로 클램프

three.js로 실제 도형을 만드는 부분은 브라우저로 확인한다.

## 하지 않는 것

- 드래그 자유 배치 (자동 배치로 결정)
- 해금·재화 — 전부 열려 있다
- 오브젝트별 색·크기 지정 UI
- 오브젝트가 지면 곡률을 따라 기우는 처리
- ⑤ 이미지→3D 캐릭터 — 이 카탈로그에 항목이 하나 느는 형태로 다음에 얹는다
