# 행성 위 걸어다니기 — 설계

작성: 2026-08-13
관련 원본: `docs/SSOT.md` (행성 꾸미기 카탈로그·자리), `docs/superpowers/specs/2026-08-13-planet-decor-design.md`

## 무엇을 만드나

개인 행성(밤하늘)에서 **한 자리에 서서 둘러보는 것**을 넘어 **걸어다닐 수 있게** 한다. 앞으로 걸으면 지평선 너머에서 꾸미기 오브젝트가 올라오고, 지나가면 뒤로 사라진다.

## 왜

지금 카메라는 별 위 한 점에 고정되어 있다(`controls.minDistance = maxDistance = 2`). 그래서 이 행성의 지평선이 30밖에 안 된다는 사실이 **제약**으로만 작동했다 — 꾸미기 오브젝트를 25~75에 몰아넣어야 했고, 그보다 멀면 행성이 스스로 가려 보이지 않았다.

걸을 수 있으면 같은 사실이 **재미**가 된다. 좁은 지평선은 "다가가면 새로운 것이 넘어온다"가 되고, 배치 범위를 좁힐 이유도 사라진다.

## 핵심 결정 — 카메라가 아니라 행성을 돌린다

지금 씬은 하늘돔(반경 750)·언덕 능선(620)·곡 별 돔(430)·잔별·유성이 전부 서 있는 지점 `C`를 중심으로 붙어 있다. 카메라를 구 표면 위로 실제로 옮기면 이것들이 모두 따라와야 해서 `enterSky`를 통째로 다시 짜야 한다.

**카메라는 그대로 두고 행성만 발밑에서 회전시킨다.** 화면에 보이는 결과는 같고, 기존 구성 요소는 한 줄도 바뀌지 않는다.

| | 행성과 함께 돈다 | 제자리 (뷰어 기준) |
| --- | --- | --- |
| 지면 구 (반경 300) | ○ | |
| 발밑 별빛 글로우 | ○ (걸어가면 뒤로 멀어진다 — 내 별의 심장을 떠나는 셈) | |
| 꾸미기 오브젝트 | ○ | |
| 하늘돔 · 곡 별 · 잔별 | | ○ (하늘은 무한히 멀다 — 걸어도 안 움직이는 것이 맞다) |
| 언덕 실루엣 (620) | | ○ (지평선을 만드는 장치이지 갈 수 있는 장소가 아니다) |
| 유성 | | ○ |

구현: 지면 구의 중심(`C - up*298.5`)에 피벗 `THREE.Group`을 두고, 지면과 꾸미기를 그 자식으로 넣는다. 앞으로 걷기는 그 피벗을 회전시키는 것이다.

```
axis  = up × forward        (시선의 수평 성분에서 구한다)
각속도 = speed / GROUND_RADIUS       // 표면 이동 속도 → 각속도
pivot.rotateOnWorldAxis(axis, -각속도 * dt)
```

**월드 축 회전은 원점을 지난다.** 피벗의 위치가 곧 회전 중심이 되도록 지면과 꾸미기를 피벗 **로컬 좌표**로 넣어야 한다 — 지금처럼 월드 좌표로 넣고 피벗만 옮기면 행성이 엉뚱한 축으로 돈다.

## 곡률에 맞춰 세우기

지금 꾸미기는 전부 `+Y`가 위인 채로 놓인다. 정수리 근처(거리 25~75, 최대 14°)라 티가 나지 않았지만, 행성이 돌면 옆으로 넘어간 것처럼 보인다. 각 오브젝트를 **자기 자리의 법선 방향**으로 세운다:

```ts
obj.quaternion.setFromUnitVectors(new THREE.Vector3(0, 1, 0), normal);
```

`normal`은 지면 구 중심에서 그 오브젝트 위치로 향하는 단위 벡터다. 이전 스펙의 "하지 않는 것"에 있던 항목인데, 걸어다니게 되면 필수가 된다.

## 조작

| | |
| --- | --- |
| PC | 방향키 / WASD. 시선(드래그)의 수평 방향이 앞이다 |
| 폰 | 화면 왼쪽 아래 가상 조이스틱 (하단 곡 캐러셀 위) |
| 정지 | 키를 떼면 즉시 멈춘다. 가속·관성 없음 — 작은 행성에서 미끄러지면 멀미가 난다 |

속도는 초당 40. 둘레가 `2π × 300 = 1885`이므로 한 바퀴 **약 47초**. 지평선이 30이라 걷는 내내 새로운 것이 넘어온다.

키 입력은 `keydown`/`keyup`으로 눌린 키 집합을 들고, 프레임 루프에서 매 프레임 회전에 반영한다(키 반복 이벤트에 의존하면 프레임률에 따라 속도가 달라진다).

**입력을 가로채지 않아야 하는 곳**: 밤하늘이 아닐 때, 그리고 텍스트 입력에 포커스가 있을 때는 방향키를 그대로 흘려보낸다 — 프로필 편집 드로어의 입력칸에서 방향키가 먹히지 않으면 안 된다.

## 실패·경계

| 상황 | 처리 |
| --- | --- |
| 행성을 나갔다 다시 들어옴 | 회전은 `enterSky`에서 초기화된다. 어디까지 걸었는지는 저장하지 않는다 — 착륙은 늘 내 별 위에서 시작한다 |
| 행성→행성 이동 | 피벗은 `skyGroup`의 자식이므로 `exitSky`의 dispose 경로를 그대로 탄다 |
| 곡 별 클릭·라벨 | 하늘은 돌지 않으므로 지금 그대로 동작한다 |
| 걷는 중 카드 캐러셀·알약 조작 | 키 입력만 쓰므로 충돌하지 않는다. 조이스틱은 `pointer-events`가 자기 영역에만 걸린다 |
| 남의 행성 | 걷는 것은 누구나 된다. 꾸미기는 여전히 주인만 |

## 테스트

`node:test`로 검증할 수 있는 것은 순수 함수뿐이다(DOM/WebGL 하네스는 없고 `npm install`이 멈춰 추가할 수도 없다). 그래서 회전 수학을 순수 함수로 떼어 테스트한다:

- `walkStep(forward, up, keys, dt, speed, radius)` → `{ axis, angle }` — 앞/뒤/좌/우 조합, 대각선일 때 속도가 √2배가 되지 않는지(정규화), 아무 키도 없으면 `angle === 0`
- `surfaceNormal(localPos)` → 단위 벡터 — 길이 1, 방향 보존

three.js로 실제로 도는 것과 조작감은 브라우저로 확인한다.

## 하지 않는 것

- **자리 직접 지정** — 다음 작업(B). 걸어다니기가 선 뒤에 그 위에 얹고, 그때 좌표를 저장하도록 스키마를 넓힌다
- 3인칭·캐릭터 모델 (1인칭으로 결정)
- 달리기·점프·충돌
- 걸어간 위치 저장
- 은하(행성 밖)에서의 이동 방식 변경
