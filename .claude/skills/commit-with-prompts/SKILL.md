# Commit with Prompts

커밋 메시지에 "이 커밋을 만들어낸 사용자 프롬프트"를 원문 그대로 기록하는 스킬.
목적은 기록이다: 나중에 `git log`를 보는 사람이 코드 변경과 함께 **어떤 프롬프트가 이 변경을 만들었는지** 볼 수 있어야 한다.

## 프롬프트 수집 규칙

1. **범위**: 현재 대화에서 이 커밋에 담기는 변경을 만들어낸 사용자 메시지들을 모은다.
   - 이 세션의 첫 커밋이면: 세션 시작부터 지금까지의 프롬프트.
   - 이미 이 세션에서 커밋한 적이 있으면: 마지막 커밋 이후의 프롬프트만.
   - 한 세션의 작업을 여러 커밋으로 나누는 경우: 각 커밋에는 그 커밋의 변경을 유발한 프롬프트만 넣는다.
2. **원문 그대로**: 오타, 반말, 한/영 혼용 모두 그대로 둔다. 다듬거나 번역하지 않는다. 원문이 기록의 가치이기 때문이다.
3. **제외할 것**:
   - 시스템 리마인더, 도구 출력, Claude의 응답 — 사용자가 직접 타이핑한 메시지만 넣는다.
   - 커밋 자체를 요청하는 프롬프트("커밋해줘" 등)는 개발 내용과 무관하므로 생략해도 된다. 단, 커밋 요청에 개발 지시가 섞여 있으면 포함한다.
   - API 키, 토큰, 비밀번호 등 민감정보가 프롬프트에 있으면 해당 부분만 `[REDACTED]`로 치환하고 사용자에게 알린다.
4. **긴 붙여넣기**: 사용자가 에러 로그나 긴 코드를 통째로 붙여넣은 경우, 지시문 부분은 그대로 두고 붙여넣은 덩어리는 `[에러 로그 N줄 첨부]`처럼 요약 표기한다. 커밋 메시지가 수백 줄이 되는 것을 막기 위함이다.

## 커밋 메시지 형식

```
<타입>: <변경 요약 한 줄>

<필요하면 변경 내용 설명>

[Prompts]
1. 첫번째 프롬프트 원문
2. 두번째 프롬프트 원문
   여러 줄 프롬프트는 이렇게 들여쓰기로 줄바꿈 유지
```

- 첫 줄(제목)은 일반적인 커밋 컨벤션을 그대로 따른다. 프롬프트는 본문의 `[Prompts]` 섹션에만 넣는다.
- 프롬프트가 하나뿐이면 번호 없이 한 줄로 써도 된다.
- 커밋 실행은 heredoc을 사용해 줄바꿈이 보존되게 한다:

```bash
git commit -m "$(cat <<'EOF'
feat: 재생목록 셔플 기능 추가

[Prompts]
1. 재생목록에 셔플 버튼 추가해줘
2. 셔플 눌렀을때 지금 나오는 노래는 끊기지 않고 그대로 재생되게 해줘
EOF
)"
```

## 예시

세션에서 사용자가 입력한 메시지:
- "곡 검색할때 초성검색도 되게 해줘"
- "ㄱㄴㄷ 순 정렬도 깨지는데 같이 고쳐줘"
- "커밋해줘"

만들어지는 커밋 메시지:

```
feat: 곡 검색 초성검색 지원 및 한글 정렬 수정

[Prompts]
1. 곡 검색할때 초성검색도 되게 해줘
2. ㄱㄴㄷ 순 정렬도 깨지는데 같이 고쳐줘
```
