# SSOT (Single Source of Truth)

모든 지식은 **정확히 한 곳**에만 정의하고, 나머지는 전부 그 한 곳에서 참조하거나 파생시킨다.
같은 사실이 두 곳에 적혀 있으면 언젠가 반드시 어긋난다 — 중복을 만드는 순간이 버그를 심는 순간이다.

## 핵심 규칙

1. **정의하기 전에 검색한다.** 새 타입, 상수, 유틸 함수, 설정값을 만들기 전에 먼저 기존 정의를 검색(Grep)한다. 이미 있으면 재사용하고, 비슷한 것이 있으면 새로 만들지 말고 기존 것을 확장한다.
2. **한 곳에 정의하고 파생시킨다.**
   - 데이터 구조: 스키마(예: zod, DB 스키마)를 원본으로 두고 타입은 추론(`z.infer` 등)으로 파생한다. 스키마 따로 타입 따로 손으로 쓰지 않는다.
   - 상수·설정: 매직 넘버/문자열을 코드 여기저기 흩뿌리지 않는다. 한 모듈에 정의하고 import해서 쓴다.
   - 계산 가능한 값: 저장하지 않고 원본에서 계산한다. (예: 곡 수를 별도 필드로 저장하지 말고 목록 길이에서 구한다. 성능상 캐시가 필요하면 "이건 파생 캐시"임을 명시하고 무효화 규칙을 함께 정의한다.)
   - 환경/설정값: `.env` → 단일 config 모듈을 거쳐서만 접근한다. `process.env`를 코드 곳곳에서 직접 읽지 않는다.
3. **복사-붙여넣기 금지.** 같은 로직이 두 번째로 필요해지는 순간이 공통 모듈로 추출할 시점이다. 두 곳에 비슷한 코드를 두지 않는다.
4. **문서보다 코드가 진실.** 문서에 코드 내용을 중복 서술하지 않는다. 문서는 "왜"와 "어디에 원본이 있는지"만 적는다.
5. **원본을 옮기면 참조를 전부 갱신한다.** 원본 정의를 이동/변경할 때는 프로젝트 전체를 검색해서 참조하는 모든 곳을 함께 수정하고, SSOT 문서도 갱신한다.

## SSOT 문서 (`docs/SSOT.md`)

각 종류의 "진실"이 어디에 사는지 기록하는 레지스트리는 **`docs/SSOT.md`** 파일에 저장한다. 이 문서 자체가 "원본이 어디 있는가"에 대한 단일 진실이다.

- **코드를 작성하기 전에** `docs/SSOT.md`를 먼저 읽어서 이미 원본이 있는지 확인한다.
- **새로운 원본 정의 위치가 생기면** 즉시 `docs/SSOT.md`에 추가한다. 파일이 없으면 아래 형식으로 생성한다.
- **원본을 이동/폐기하면** 해당 행을 함께 수정/삭제한다.
- SSOT 문서는 코드 변경과 **같은 커밋**에 포함시켜서 문서와 코드가 어긋나지 않게 한다.

`docs/SSOT.md` 형식:

```markdown
# SSOT 맵

이 프로젝트의 모든 "진실의 원본"이 어디에 사는지 기록하는 레지스트리.
코드를 작성하기 전에 이 표를 먼저 확인할 것. 여기 없는 원본을 새로 만들면 이 표에 추가할 것.

| 지식의 종류 | 원본 위치 | 파생물 | 비고 |
| --- | --- | --- | --- |
| 데이터 스키마 | `src/schemas/` | 타입(`z.infer`) | 타입 직접 정의 금지 |
| 앱 설정/환경변수 | `src/config.ts` | — | `process.env` 직접 접근 금지 |
| UI 상수(색상, 크기) | `src/constants/ui.ts` | — | |
```

(위 표의 행들은 예시다. 실제 프로젝트 구조가 잡히는 대로 실제 위치로 채운다.)

## 커밋 전 자가 점검

커밋하기 전에 다음을 확인한다:

- [ ] 이번 변경에서 같은 값/타입/로직을 두 곳 이상에 정의하지 않았는가?
- [ ] 새로 만든 원본 정의가 있다면 `docs/SSOT.md`에 기록했는가? (문서 변경을 같은 커밋에 포함)
- [ ] 기존 원본을 수정했다면 참조하는 모든 곳이 함께 갱신되었는가?
